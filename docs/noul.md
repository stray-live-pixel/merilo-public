# Noul: проверить важное утверждение

Примеры результатов ниже иллюстративные: показаны только поля, необходимые для разбора, а не реальные замеры.

## Заметить просьбу о возврате в общей очереди

### Задача пользователя

Ты разбираешь обращения магазина. Нужно выделить сообщения, в которых клиент просит вернуть деньги, чтобы не оставить их в очереди обычных вопросов.

### Запрос

```bash
args=(
  -api-key "$OPENROUTER_API_KEY"
  -model deepseek/deepseek-v4.1-flash
  -effort xhigh
  -type noul
  -question 'Просит ли клиент вернуть деньги? Отличай явную просьбу от вопроса о правилах возврата.'  # Что важно для этой задачи.
)

# Материал, который требуется оценить.
merilo "${args[@]}" -context - <<'TEXT'
Заказ 1842 отменили неделю назад. Прошу вернуть списанные 3200 рублей на карту.
TEXT
```

### Пример результата

```json
{
  "type": "noul",
  "noul": 0.98,
  "completed": 1
  ...
}
```

### Как использовать результат

Сообщение можно пометить как просьбу о возврате и передать ответственному сотруднику. Значение 0.98 отражает оценку наличия просьбы. Оно не означает, что возврат одобрен: право на него и состояние платежа проверяются отдельно.

## Проверить, готов ли заказ к закрытию

### Задача пользователя

Менеджер закрывает выполненные заказы. Перед этим нужно убедиться, что по предоставленной сводке не осталось неоплаченных счетов.

### Запрос

```bash
args=(
  -api-key "$OPENROUTER_API_KEY"
  -model deepseek/deepseek-v4.1-flash
  -effort xhigh
  -type noul
  -question 'Все ли счета по заказу оплачены полностью? Считай счёт с частичной оплатой неоплаченным.'  # Что важно для этой задачи.
)

# Материал, который требуется оценить.
merilo "${args[@]}" -context - <<'TEXT'
Заказ 518. Счёт A: сумма 5000, оплачено 5000. Счёт B: сумма 3000, оплачено 2000.
TEXT
```

### Пример результата

```json
{
  "type": "noul",
  "noul": 0.02,
  "completed": 1
  ...
}
```

### Как использовать результат

Низкое значение означает, что утверждение «всё оплачено» скорее неверно. В самой сводке видно, что по счёту B остаётся 1000. Менеджеру стоит сверить остаток с платёжной системой перед закрытием заказа. Число не объясняет причину автоматически — здесь она известна из исходных данных.

## Найти противоречие перед отправкой письма клиенту

### Задача пользователя

Ты готовишь ответ о сроках доставки. Нужно заметить несовместимые обещания до того, как письмо уйдёт клиенту.

### Запрос

```bash
args=(
  -api-key "$OPENROUTER_API_KEY"
  -model deepseek/deepseek-v4.1-flash
  -effort xhigh
  -type noul
  -repeats 5  # Несколько оценок одного материала.
  -question 'Содержит ли письмо противоречащие друг другу обещания о сроках доставки одного заказа?'  # Что важно для этой задачи.
)

# Материал, который требуется оценить.
merilo "${args[@]}" -context - <<'TEXT'
Ваш заказ доставим завтра, 12 октября. Доставка этого же заказа назначена на 15 октября; изменить эту дату нельзя.
TEXT
```

### Пример результата

```json
{
  "type": "noul",
  "aggregation": "median",
  "noul": 0.96,
  "repeats": 5,
  "completed": 5
  ...
}
```

### Как использовать результат

Письмо стоит вернуть автору для уточнения даты. В тексте одновременно обещаны 12 и 15 октября. Высокая оценка помогает выделить письмо для проверки, но исправленную дату нужно взять из данных заказа, а не угадать по результату классификатора.
