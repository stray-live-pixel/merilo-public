# Score: оценить материал перед следующим шагом

Примеры результатов ниже иллюстративные: показаны только поля, необходимые для разбора, а не реальные замеры.

## Понять, готова ли инструкция для нового клиента

### Задача пользователя

Ты выпускаешь инструкцию по оплате. Она должна помогать человеку, который впервые открыл продукт, выполнить действие без обращения в поддержку.

### Запрос

```bash
args=(
  -api-key "$OPENROUTER_API_KEY"
  -model deepseek/deepseek-v4.1-flash
  -effort xhigh
  -type score
  -repeats 5  # Несколько оценок одного материала.
  -question 'Оцени понятность инструкции для нового клиента: ясно ли, куда перейти, что нажать и как понять, что действие завершено.'  # Что важно для этой задачи.
  -levels 'Новичок не сможет понять порядок действий|Новичок сможет выполнить действия без догадок'  # От худшего состояния к лучшему.
)

# Материал, который требуется оценить.
merilo "${args[@]}" -context - <<'TEXT'
Откройте раздел «Счета», выберите нужный счёт и нажмите «Оплатить». После оплаты дождитесь статуса «Оплачен» рядом с номером счёта.
TEXT
```

### Пример результата

```json
{
  "type": "score",
  "aggregation": "median",
  "score": 0.9,
  "repeats": 5,
  "completed": 5
  ...
}
```

### Как использовать результат

Оценка близка к полюсу «можно выполнить без догадок». Инструкцию можно передать на проверку в самом интерфейсе: действительно ли разделы и статусы называются так. Результат поддерживает решение двигаться дальше, но не подтверждает существование кнопок.

## Разобрать сообщения об ошибках по серьёзности

### Задача пользователя

В очередь разработки пришло несколько дефектов. Нужно отличать косметические неудобства от проблем, которые блокируют работу пользователя.

### Запрос

```bash
args=(
  -api-key "$OPENROUTER_API_KEY"
  -model deepseek/deepseek-v4.1-flash
  -effort xhigh
  -type score
  -question 'Оцени влияние дефекта на выполнение задачи пользователя. Учитывай наличие обходного пути.'  # Что важно для этой задачи.
  -levels 'Только косметическое неудобство|Функция нарушена, но есть обходной путь|Задача заблокирована, обходного пути нет'  # От худшего состояния к лучшему.
)

# Материал, который требуется оценить.
merilo "${args[@]}" -context - <<'TEXT'
Экспорт в PDF не работает. Пользователь может скачать документ в DOCX и сохранить его как PDF через редактор.
TEXT
```

### Пример результата

```json
{
  "type": "score",
  "score": 1.1,
  "probabilities": {
    "0": 0,
    "1": 0.9,
    "2": 0.1
  }
  ...
}
```

### Как использовать результат

Балл близок ко второму уровню: функция нарушена, но задача остаётся выполнимой. Такой дефект можно сопоставить с другими по влиянию. Приоритет исправления команда определяет с учётом числа затронутых клиентов и важности экспорта.

## Оценить готовность ответа службы поддержки

### Задача пользователя

Руководитель поддержки хочет замечать ответы, которые формально вежливы, но не помогают клиенту. Нужна шкала от отсутствия помощи до понятного пути решения.

### Запрос

```bash
args=(
  -api-key "$OPENROUTER_API_KEY"
  -model deepseek/deepseek-v4.1-flash
  -effort xhigh
  -type score
  -question 'Оцени полезность ответа поддержки: отвечает ли он на проблему и даёт ли клиенту понятный следующий шаг.'  # Что важно для этой задачи.
  -levels 'Не отвечает на проблему|Признаёт проблему, но не помогает действовать|Даёт полезный шаг, но оставляет важные вопросы|Даёт понятный путь решения и дальнейшие действия'  # От худшего состояния к лучшему.
)

# Материал, который требуется оценить.
merilo "${args[@]}" -context - <<'TEXT'
Клиент: после оплаты подписка не появилась. Ответ: проверьте, что вошли с адресом, указанным при оплате. Если адрес совпадает, пришлите номер заказа: мы проверим активацию.
TEXT
```

### Пример результата

```json
{
  "type": "score",
  "score": 2.4,
  "probabilities": {
    "0": 0,
    "1": 0,
    "2": 0.6,
    "3": 0.4
  }
  ...
}
```

### Как использовать результат

Оценка находится между «полезным шагом» и «понятным путём решения». Ответ уже помогает клиенту, но руководитель может проверить, достаточно ли ясно описан дальнейший процесс. Почему получилось именно 2.4, а не число до единицы, объясняется отдельно в [методике оценки](methodology.md).
