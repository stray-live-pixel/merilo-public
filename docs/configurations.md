# Конфигурации: один материал, несколько вопросов

Примеры результатов ниже иллюстративные: показаны только поля, необходимые для разбора, а не реальные замеры.

## Подготовить объявление об изменении продукта

### Задача пользователя

Ты публикуешь изменение правил входа. Перед отправкой нужно одновременно проверить понятность текста, наличие следующего шага и целевую аудиторию. Набор вопросов сохранён в [announcement-review.json](announcement-review.json), чтобы команда использовала его и для следующих объявлений.

### Запрос

```bash
# Оцениваем одно объявление по трём вопросам редактора.
merilo \
    -api-key "$OPENROUTER_API_KEY" \
    -config docs/announcement-review.json \
    -context 'С 1 ноября администраторы должны включить двухфакторную аутентификацию. Откройте «Настройки → Безопасность» и подключите приложение для кодов. Остальным пользователям ничего менять не нужно.'
```

### Пример результата

```json
{
  "checks": [
    {
      "id": "clarity",
      "category": "Понятность",
      "score": 0.9,
      "status": "completed"
    },
    {
      "id": "action",
      "noul": 0.98,
      "status": "completed"
    },
    {
      "id": "audience",
      "choice": "администраторы",
      "status": "completed"
    }
  ]
  ...
}
```

### Как использовать результат

Текст получил положительную оценку понятности, содержит действие и адресован администраторам. Редактор может перейти к проверке фактической даты и названий разделов. Это три самостоятельных ответа: сильная понятность не компенсирует ошибку в аудитории. Решение о публикации остаётся у редактора.

## Подготовить код к обсуждению с командой

### Задача пользователя

Перед ревью ты хочешь увидеть профиль качества кода: читаемость, оформление, комментарии, декомпозицию и организацию функций. Это помогает выбрать темы для обсуждения, вместо одного расплывчатого вопроса «код хороший?». В [code-quality.json](code-quality.json) уже собраны восемь аспектов.

### Запрос

```bash
# Передаём исходники приложения как единый материал для обсуждения.
cat /path/to/your/project/*.go |
  merilo \
    -api-key "$OPENROUTER_API_KEY" \
    -config docs/code-quality.json \
    -context -
```

### Пример результата

```json
{
  "checks": [
    {
      "id": "readability",
      "score": 0.88,
      "status": "completed"
    },
    {
      "id": "formatting",
      "score": 0.95,
      "status": "completed"
    },
    {
      "id": "decomposition",
      "score": 0.55,
      "status": "completed"
    },
    {
      "id": "responsibility",
      "score": 0.6,
      "status": "completed"
    }
  ]
  ...
}
```

### Как использовать результат

В этом фрагменте отчёта оформление оценено выше, чем декомпозиция и разделение обязанностей. Команда может начать обсуждение со структуры функций, а не со стиля отступов. Модель не назвала конкретные дефекты: их следует найти при чтении кода. Такой профиль помогает направить внимание, но не означает автоматическое одобрение ревью.
