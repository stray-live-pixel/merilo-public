# Запуск и обработка результатов

Этот документ описывает техническую работу с инструментом. Пользовательские задачи — в [каталоге сценариев](examples.md).

## Подготовка

Установите готовый Merilo по [инструкции](../README.md#установка-и-обновление). Go не нужен. Скачайте нужные JSON-примеры из документации в рабочую папку задачи; пути в командах отсчитываются от неё.

```bash
export OPENROUTER_API_KEY='ваш-ключ'
```

CLI не читает окружение автоматически: ключ передаётся через -api-key. Модель и effort задаются явно или в JSON-конфиге. Их поддержка зависит от провайдера OpenRouter; реальные вызовы платные.

В сценариях используется массив Bash args: он позволяет оставить комментарии рядом с отдельными параметрами. Выражение "${args[@]}" передаёт элементы массива без потери пробелов. Это конструкция shell, а не дополнительная функция приложения.

Конфигурация передаётся как путь `-config file.json` или как JSON-объект прямо в аргументе `-config '{"defaults": {...}, "checks": [...]}'`. Оба способа используют одинаковую схему. В JSON нет поля context; текст всегда передаётся отдельно.

Текст задаётся через обязательный -context. Позиционный текст и чтение stdin без этого флага не поддерживаются. Значение -context - означает чтение stdin. Quoted heredoc <<'TEXT' передаёт многострочный текст без подстановок shell.

## Контракт CLI

Параметры, наследование настроек, повторы, медиана, коды выхода и __external__ описаны в [README](../README.md). Медиана score не нормализуется автоматически. При неполной серии итог отсутствует, но доступные результаты и расход сохраняются.

# Поля результата и jq

Сохрани результат CLI в /tmp/merilo-results.json. Ниже команды для jq; это внешний инструмент, не зависимость CLI.

| Задача | Команда |
|---|---|
| Увидеть результаты всех проверок | `jq '.checks[] \| {id, status, score, noul, choice}' /tmp/merilo-results.json` |
| Увидеть каждый повтор score-проверки | `jq '.checks[] \| select(.id == "readability") \| .samples[].result.score' /tmp/merilo-results.json` |
| Получить стоимость и токены всего запуска | `jq '{usage, usage_complete, attempt_count}' /tmp/merilo-results.json` |
| Передать результат и метаданные дальше | `jq '.checks[] \| {id, score, __external__}' /tmp/merilo-results.json` |
| Найти технические ошибки | `jq '.checks[] \| select(.status == "error")' /tmp/merilo-results.json` |

| Поле | Значение |
|---|---|
| score / noul | Одиночное значение или медиана повторов |
| choice | Выбранная категория |
| samples[].result | Результат отдельного успешного повтора |
| samples[].attempts | Все попытки повтора, ошибки и расход |
| usage | Суммарные доступные стоимость и токены |
| usage_complete=false | Расход неполный; неизвестное не равно нулю |
| status=completed | Все оценки получены, независимо от качества |
| status=error | Не удалось собрать все оценки |

В одиночном режиме samples и usage находятся на верхнем уровне, в конфиге — также внутри каждой проверки. Общий usage уже включает проверки и их попытки: повторно складывать его с ними нельзя.

Для пяти баллов 0.7, 0.8, 0.8, 0.85, 0.82 медиана равна 0.8. Для четырёх 0.7, 0.8, 0.82, 0.9 — 0.81. Это статистика оценок, не доказательство объективного качества.

Если повторов не хватило, CLI возвращает доступную статистику и код выхода 1 без итоговой медианы этой проверки. Отклонённый текст ответа не сохраняется, но ошибка и доступный usage остаются в attempts.
