# Оценки через Codex по подписке

Установите актуальный Codex CLI и выполните `codex login`, выбрав вход через ChatGPT. Проверьте `codex login status`. Merilo использует сохранённую авторизацию CLI и принудительно требует вход ChatGPT. API-ключ OpenRouter для Codex не нужен; автоматического перехода на платный API нет.

Нужна версия Codex CLI с `exec`, `--strict-config`, `--ephemeral`, `--ignore-user-config`, `--output-schema` и настройками изоляции, перечисленными ниже. Интеграция проверена с 0.155.0-alpha.16.4. Модель должна быть доступна вашему аккаунту; её имя берётся из Codex, а не из каталога OpenRouter. Поддержка effort зависит от модели: Merilo принимает `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`, но неподдерживаемое сочетание CLI отклонит без подмены.

```bash
merilo -provider codex -model gpt-6-sol -effort low \
  -type score -levels 'Следующий шаг непонятен|Следующий шаг понятен' \
  -question 'Насколько понятно, что сделать после ошибки?' \
  -context 'Проверьте email и отправьте форму снова.'
```

В интерфейсе выберите **Codex · подписка ChatGPT** в технических настройках. После смены провайдера укажите подходящую модель. Ключ OpenRouter запрашивается только при запуске конфигурации, которая содержит проверки OpenRouter. Экспорт команды учитывает это условие.

## Конфигурация

`provider` наследуется из `defaults` и может быть переопределён в отдельной проверке. Если его нет, используется OpenRouter — существующие конфиги продолжают работать. `model` и `effort` наследуются независимо от провайдера: при смешивании провайдеров указывайте корректную модель и effort для каждой проверки.

```json
{
  "defaults": {
    "provider": "codex",
    "model": "gpt-6-sol",
    "effort": "low",
    "repeats": 1
  },
  "concurrency": 2,
  "checks": [
    {
      "id": "clarity",
      "type": "score",
      "question": "Понятно ли пользователю следующее действие?",
      "levels": ["Непонятно", "Понятно"]
    }
  ]
}
```

Сохраните как `checks.json` и запустите `merilo -config checks.json -context 'Ваш материал'`. С `-config` провайдер задаётся в JSON, отдельный флаг `-provider` не применяется. Если хотя бы одна проверка использует OpenRouter, передайте также `-api-key`.

## Выполнение и расход

Каждая попытка запускает отдельную временную сессию `codex exec` в пустой временной папке. Merilo передаёт схему JSON и инструкции через временные файлы, а материал через stdin, затем проверяет диапазоны, набор полей и сумму вероятностей. Режимы, повторы и медианы совпадают с OpenRouter. Неверный ответ допускает три дополнительные попытки; сбой CLI, авторизации, лимитов или таймаут не повторяется автоматически. Таймаут попытки — 180 секунд.

## Codex используется как оценщик без инструментов

В Merilo Codex получает критерий, материал и схему JSON, затем возвращает оценку. Модель не получает инструменты чтения и изменения файлов, выполнения shell-команд, браузера, поиска или делегирования. Пользовательские скиллы, плагины, память и AGENTS.md не добавляются. В запросе к модели **нет инструментов**: нет определений ни в поле `tools`, ни в элементах `input` с типом `additional_tools`. Проверка только верхнего поля `tools` недостаточна: Codex может передавать инструменты внутри `input`.

Такое ограничение приближает поведение к вызову OpenRouter: оценка зависит от явно переданного материала, а модель не исследует репозиторий, не выполняет действия и не запускает цикл вызовов инструментов. Сам Codex CLI читает файлы инструкций, схемы и каталога, работает с авторизацией и сохраняет ответ для Merilo; это действия программы, а не инструменты, доступные модели.

Эти параметры обязательны для каждого запуска Codex из Merilo: через CLI, интерфейс, JSON-конфиг, а также для каждой повторной попытки. Они не настраиваются пользователем через конфигурацию проверок:

| Что исключается | Настройки Codex |
|---|---|
| Shell и чтение локальных изображений | `features.shell_tool=false`, `features.unified_exec=false`, `features.view_image=false` |
| Браузер, управление компьютером, изображения и поиск | `features.browser_use=false`, `features.computer_use=false`, `features.image_generation=false`, `web_search="disabled"` |
| Code Mode и его инструменты | `features.code_mode=false`, `features.code_mode_host=false` |
| Цели, ожидание, планирование, вопросы пользователю и делегирование | `features.goals=false`, `features.sleep_tool=false`, `tools.update_plan.enabled=false`, `tools.experimental_request_user_input.enabled=false`, `features.multi_agent=false`, `features.multi_agent_v2=false` |
| Плагины, коннекторы и предложение инструментов | `features.apps=false`, `features.plugins=false`, `features.remote_plugin=false`, `features.tool_suggest=false` |
| Скиллы, память и hooks | `features.skip_host_skill_discovery=true`, `features.skill_search=false`, `features.memories=false`, `features.hooks=false` |
| Пользовательский конфиг и инструкции проекта | `--ignore-user-config`, `project_doc_max_bytes=0`; свои инструкции через `model_instructions_file` |

### Почему дополнительно используется временный каталог модели

Метаданные GPT-6 во встроенном каталоге могут включать Code Mode, `apply_patch`, служебные инструменты и делегирование независимо от части feature-флагов. Поэтому одних флагов недостаточно.

Перед каждой попыткой Merilo читает `codex debug models --bundled` и создаёт временный каталог только для выбранной модели. Имя модели, уровни рассуждений, контекстные лимиты и остальные параметры сохраняются. Переопределяются только возможности инструментов и добавления инструкций скиллов/плагинов:

- `shell_type="disabled"`, `apply_patch_tool_type=null`;
- `experimental_supported_tools=[]`, `supports_search_tool=false`;
- `tool_mode=null`, `multi_agent_version=null`, `node_repl_disabled=true`;
- `include_skills_usage_instructions=false`, `include_plugin_usage_instructions=false`, `include_apps_usage_instructions=false`.

Этот файл передаётся через `model_catalog_json` и удаляется вместе с временной папкой. Пользовательский каталог и настройки Codex не изменяются. Если выбранной модели нет во встроенном каталоге или каталог не читается, Merilo возвращает ошибку **до запроса оценки**, не переключая модель и не запуская Codex с обычным набором инструментов. В таком случае нужен новый CLI или модель из `codex debug models --bundled`.

Дополнительно включены `--ephemeral`, `--sandbox read-only`, `approval_policy="never"` и запуск из временной папки. Sandbox и текст «не используй инструменты» сами по себе не обеспечивают пустой список инструментов: для этого нужны перечисленные отключения. `--strict-config` отклоняет неизвестные настройки вместо их молчаливого игнорирования.

**Ретраи и параллелизм сохраняются.** Ими, валидацией и медианой управляет Merilo через тот же механизм, что и для OpenRouter. Запрет относится к действиям модели внутри одной попытки, а не к количеству независимых оценок или повторных попыток. Параметр `service_tier` не передаётся.

## Авторизация и учёт расхода

Авторизацию читает сам Codex; Merilo не читает и не копирует токены. Временные инструкции, каталог, схема и результат удаляются после попытки. Диагностика CLI не включается в отчёт, поскольку может содержать исходный материал; при сбое Merilo предлагает проверить вход, лимиты и настройки CLI.

Результат содержит `provider: "codex"`, `billing: "chatgpt_subscription"`, модель, effort и доступные счётчики токенов. `usage.cost` отсутствует, `usage_complete: false`: подписка не даёт достоверной цены отдельного запроса. В смешанной конфигурации стоимость показывает только известную часть расхода. В UI отсутствие цены обозначается «—».

Оценки используют лимиты того же аккаунта Codex, что и разработка. Начинайте с одного повтора и небольшого параллелизма. Не сравнивайте баллы разных провайдеров как измерения одной неизменной модели.
