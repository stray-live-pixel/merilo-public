# Как строить оценку

Методика помогает выбрать вопрос и интерпретировать ответ. Готовые пользовательские задачи находятся в [каталоге сценариев](examples.md).

## Выбор режима

Choice подходит для выбора одного маршрута или категории. Noul — для оценки истинности одного утверждения. Score — для положения на упорядоченной шкале качества.

Формулируй критерии так, чтобы разные материалы можно было сравнить по одному правилу. Указывай аудиторию и контекст: понятность инструкции для нового клиента и для сотрудника поддержки — разные задачи.

Если нужны отдельные выводы о понятности, логике и полноте, используй отдельные проверки. Один составной балл не показывает, какой аспект слабее.

## Повторы и сравнение

Для сравнения версий сохраняй модель, effort, вопрос, уровни и число повторов. Медиана уменьшает влияние отдельных крайних оценок, но не устраняет общие ошибки модели. Смотри также на отдельные результаты и разброс.

Полезно проверять критерии на известных примерах: понятная и запутанная инструкции, письмо с просьбой о возврате и без неё. Порог принятия решения выбирает владелец процесса; CLI его не применяет.

Высокая оценка не заменяет подтверждение фактов или проверку поведения программы. Когда требуется объяснение недостатка, числовой результат сам по себе его не даёт. Не приписывай модели причины, которых нет в ответе.

## Уровни score

Укажи от 2 до 10 уровней от низшего к высшему. Два уровня дают диапазон 0–1, четыре — 0–3. Описания должны различать состояния материала, а не быть только числами.

## Откуда берётся 2.4

Пусть четыре уровня означают «очень плохо», «плохо», «хорошо», «отлично»:

| Номер | Уровень | Вероятность модели | Вклад в score |
|---|---|---:|---:|
| 0 | Очень плохо | 0 | 0 |
| 1 | Плохо | 0 | 0 |
| 2 | Хорошо | 0.6 | 1.2 |
| 3 | Отлично | 0.4 | 1.2 |
| **Итого** | | **1** | **2.4** |

Score — взвешенная позиция на шкале: `Σ(i × p[i])`. Число 2.4 находится между уровнями 2 и 3. Это не вероятность 240% и не выбор несуществующей категории «2.4».

| Что суммируем | Должно равняться 1? |
|---|---|
| Вероятности уровней одного ответа | Да |
| Итоговый score | Нет |
| Баллы разных проверок в конфиге | Нет |
| Медианы вероятностей разных уровней | Не обязательно |

Если внешнему инструменту нужна шкала 0–1, он может разделить score на N−1: `2.4 / 3 = 0.8`. CLI такую нормализацию балла не выполняет.

Для двух полюсов при необходимости дополни question: «Два описания — полюса одной шкалы. Верни вес верхнего s и нижнего 1-s; сумма равна 1». Это помогает избежать трактовки уровней как независимых утверждений.

## Ручной подбор с агентом

Для свободного вопроса скилл сначала помогает выбрать модель и effort. Простая
категоризация обычно оправдывает экономную модель с низким effort; неоднозначный
контекст может потребовать более сильной модели. Это начальная гипотеза, которую
нужно проверять на материалах с известным ответом.

После выбора модели агент предлагает режим и полезную альтернативу на вашем кейсе.
Например, `choice` выбирает один отдел для обращения, а несколько проверок `noul`
позволяют независимо отметить просьбу о возврате и сообщение об ошибке. `score`
подходит для положения на шкале срочности; `choice` — для фиксированного ярлыка.
Разные признаки не следует усреднять как повторы одной проверки.

Один вызов экономит время и расход на первом примере. Серия из 3–5 повторов помогает
увидеть разброс; для `score` и `noul` результат — медиана чисел, для `choice` —
категория с максимальной медианной вероятностью, а не большинство голосов.
Дополнительные вызовы расходуют ресурсы и не устраняют систематические ошибки модели.
Пользователь согласует конкретный вариант перед запуском; готовый пользовательский
конфиг не требует повторного выбора настроек.

## От примера к регулярному процессу

После реальной оценки агент может помочь подготовить конфиг и CLI-команду, адаптер
для потока материалов и проверку качества на размеченной выборке. Один запуск Merilo
получает один контекст; очередь, расписание, пороги принятия решений и маршрутизация
реализуются снаружи CLI. Ошибки выполнения и спорные результаты должны иметь отдельный
путь обработки. Для повторных запусков закрепляйте настройки; качество процесса нельзя
подтвердить одним удачным примером.
