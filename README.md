# Мерило (`merilo`)

Публичная документация и дистрибутивы приложения. Готовые версии находятся в [Releases](https://github.com/stray-live-pixel/merilo-public/releases).

Минимальный Go CLI для классификации и оценки текста через OpenRouter или Codex CLI с подпиской ChatGPT. Три режима: выбор категории (`choice`), оценка по описанным уровням (`score`) и вероятность истинности утверждения (`noul`). Результат — JSON со стоимостью, токенами и историей попыток.

## Установка и обновление

Готовые релизы работают без Go: macOS и Linux, `amd64` и `arm64`.
Нужны `curl` или `wget`, `tar` и `sha256sum` или `shasum`.

### Через агента — рекомендуемый способ

Скопируйте один из промптов в агента, у которого есть доступ к терминалу вашего
компьютера. Агент выполнит установку или обновление и проверит результат.
Агент в облачной среде изменит только свою среду, а не ваш компьютер.

**Установить Merilo:**

```text
Установи последнюю стабильную версию Merilo на мой компьютер из официального
публичного репозитория https://github.com/stray-live-pixel/merilo-public.
Используй готовый релиз для моей ОС и архитектуры; Go и исходники не нужны.
Скачай https://github.com/stray-live-pixel/merilo-public/releases/latest/download/install.sh
во временный файл с проверкой успешного HTTP-ответа. При ошибке скачивания остановись.
Запусти этот файл через sh сначала с --plan и покажи версию и целевые пути,
затем выполни тот же файл с --yes: я разрешаю установку бинарника, встроенного
скилла Codex и настройку PATH, предусмотренную установщиком.
Учитывай мой CODEX_HOME, если он задан. После установки добавь каталог бинарника
в PATH текущей сессии, проверь merilo version, merilo -h и merilo skill,
а также наличие установленного SKILL.md. Удали временный установщик.
Сообщи версию, пути бинарника и скилла и как обновить список скиллов в Codex.
Не запускай оценки и не запрашивай API-ключи: для установки они не нужны.
```

**Обновить Merilo:**

```text
Обнови Merilo на моём компьютере до последней стабильной версии из официального
публичного репозитория https://github.com/stray-live-pixel/merilo-public.
Найди установленный бинарник и проверь merilo version. Выполни merilo update --yes:
я разрешаю обновление приложения и встроенного скилла Codex. Сохрани текущий
каталог установки и путь скилла; учитывай MERILO_CODEX_HOME и CODEX_HOME,
а для другого известного каталога передай --codex-home.
Если установлена старая версия, обращающаяся к приватному репозиторию,
dev-сборка или переименованный бинарник, используй установщик последнего
публичного релиза: скачай install.sh с проверкой успешного HTTP-ответа,
покажи --plan и запусти тот же файл с --yes, --install-dir и --codex-home
для согласованных путей. Если путь установки или скилла неоднозначен, уточни его.
Если приложение не найдено, сообщи об этом. Если версия уже актуальна, не переустанавливай её.
После обновления проверь merilo version, merilo -h и merilo skill,
сообщи прежнюю и текущую версии и напомни обновить список скиллов в Codex.
Не запускай оценки и не запрашивай API-ключи: для обновления они не нужны.
```

### Вручную через терминал

Установка последней стабильной версии:

```bash
curl -fsSL https://github.com/stray-live-pixel/merilo-public/releases/latest/download/install.sh | sh
```

Установщик показывает версию, пути и изменение PATH, затем спрашивает подтверждение
через терминал (по умолчанию — отказ). Бинарник устанавливается в
`~/.local/bin/merilo`, скилл — в `${CODEX_HOME:-$HOME/.codex}/skills/merilo/SKILL.md`.
Скилл извлекается из нового бинарника командой `merilo skill`, поэтому исходники
или отдельная загрузка скилла не нужны. Существующий `SKILL.md` заменяется;
личные дополнения следует хранить отдельно.

Для автоматизации скачайте установщик во временный файл и используйте **тот же файл**:

```bash
installer=$(mktemp)
curl -fsSL https://github.com/stray-live-pixel/merilo-public/releases/latest/download/install.sh -o "$installer"
sh "$installer" --plan
sh "$installer" --yes
rm "$installer"
```

`--plan` показывает план без загрузки архивов и записи файлов; `--yes` подтверждает
установку без терминала. Доступны `--version vMAJOR.MINOR.PATCH`, `--install-dir /absolute/bin`
и `--codex-home /absolute/codex`, а также `MERILO_VERSION`, `MERILO_INSTALL_DIR`,
`MERILO_CODEX_HOME`. Для пути скиллов приоритет: флаг, `MERILO_CODEX_HOME`, `CODEX_HOME`,
`~/.codex`. Скрипт из Release уже содержит точную версию; исходный `install.sh` из Git
требует `--version`.

```bash
merilo version
merilo skill
merilo update
# Для автоматизации:
merilo update --yes
# Если скиллы установлены в нестандартный каталог:
merilo update --yes --codex-home /absolute/codex
```

`update` проверяет последнюю стабильную версию GitHub, проверяет SHA-256 установщика
и запускает его для каталога текущего бинарника. Если версия уже актуальна или новее,
файлы не меняются; для восстановления скилла повторите `install.sh` той же версии.
Dev-сборки и переименованные бинарники автоматически не обновляются.

Установщик проверяет SHA-256 архива, версию бинарника и непустой встроенный скилл до
замены файлов. При ошибке замены восстанавливаются прежние бинарник, скилл и shell
profile. Это последовательные атомарные замены отдельных файлов с откатом при
обрабатываемой ошибке, а не гарантия против отключения питания или одновременных установок.
PATH добавляется один раз; для текущего терминала выполните напечатанную команду.
После установки или обновления перезагрузите список скиллов либо перезапустите Codex.
Бинарники macOS пока не подписаны и не notarized.

Здесь публикуются документация, скилл и готовые релизы. Исходники приложения и история разработки в этот репозиторий не входят.

## Провайдеры

Для OpenRouter ключ передаётся только обязательным флагом -api-key. Для Codex используется `codex login`, API-ключ не нужен. [Оценки через Codex](docs/codex.md). [Передача ключа и подготовка](docs/technical-guide.md).

Можно передать значение непосредственно: `-api-key 'ваш-ключ'`. Утилита не читает переменные окружения автоматически. Для проверок OpenRouter без непустого `-api-key` запуск завершится ошибкой до обращения к API.

Приложение не сохраняет токен на диск, не читает файл ключа или `.env` и не встраивает ключ в бинарник. Пересборка при смене токена не нужна. В JSON-конфиг токен не добавляется: `-api-key` можно сочетать с `-config`.

## Локальный интерфейс

Для интерактивных проверок запусти `merilo -ui` и открой адрес, который напечатает CLI. По умолчанию — http://127.0.0.1:8080.

Вкладки Choice, Noul, Score и конфигураций имеют свои шаблоны, формы и черновики. Технические настройки вынесены отдельно; категории и уровни редактируются списками. Провайдер выбирается в технических настройках. Ключ запрашивается при запуске проверок OpenRouter; для Codex нужен вход через `codex login`. Ключ можно сменить отдельной кнопкой. Справа — закреплённый запуск, результат и экспорт JSON/команды. Светлая и тёмная темы следуют настройкам системы.

[Запуск и работа с интерфейсом](docs/ui.md).

## Примеры

### Как выбрать режим

- **Choice — «какой вариант подходит?»** Используй, когда нужно выбрать одну категорию из списка: направить обращение в отдел, определить тему или тип сообщения. Например: «оплата», «ошибка» или «возврат». Варианты не обязаны образовывать шкалу.
- **Noul — «верно ли это?»** Используй для вопроса с ответом «да/нет»: просит ли клиент возврат, все ли счета оплачены, есть ли противоречие. Результат — оценка вероятности «да» от 0 до 1.
- **Score — «насколько хорошо или сильно?»** Используй, когда есть упорядоченная шкала: читаемость кода, понятность инструкции или серьёзность дефекта. Опиши уровни от низшего к высшему. Два уровня дают балл 0–1, четыре — 0–3; возможны дробные значения между уровнями.
- **Конфигурация — «нужно проверить сразу несколько вещей».** Это способ объединить проверки Choice, Noul и Score в один запуск. Например, определить тему обращения, проверить наличие просьбы о возврате и оценить срочность. Каждая проверка возвращает отдельный результат.

Если нужен один готовый ярлык вроде «низкая / средняя / высокая срочность», выбирай Choice. Если нужна числовая оценка между описанными уровнями срочности — Score. Noul оценивает истинность утверждения, а не качество по шкале.

## Контекст и параметры

Текст передаётся явно: `-context 'текст'` или `-context -` для чтения stdin. Флаг совместим с `-config`. Не сочетай его с позиционным текстом. Флаг -context обязателен для CLI-запросов: позиционный текст и автоматическое чтение stdin без флага не поддерживаются. Лимит — 1 000 000 байт, дополнительно действует контекстное окно модели.

`-question` входит в системную инструкцию; анализируемый текст передаётся отдельным пользовательским сообщением. Это может быть проза, код, логи или JSON. CLI не открывает ссылки, не извлекает PDF и не помнит прошлые запросы. Переданный текст отправляется выбранному провайдеру.

| Флаг | Обязателен | Значение |
|---|---|---|
| `-ui` | Для запуска веб-интерфейса | Совместим с `-port` и `-api-key` |
| `-port` | Нет | Порт UI, по умолчанию 8080 |
| `-provider` | Нет | `openrouter` (по умолчанию) или `codex`; при `-config` задаётся в JSON |
| `-api-key` | Для проверок OpenRouter | Ключ OpenRouter; в UI можно ввести в модалке. Допускается явная shell-подстановка переменной |
| `-config` | Для запуска списка проверок | Путь к файлу или JSON-конфиг прямо в аргументе; настройки проверок берутся из JSON |
| `-type` | Нет | `choice` (по умолчанию), `score`, `noul` |
| `-model` | Да для одиночного CLI-запроса без `-config` | Идентификатор модели выбранного провайдера; при `-config` задаётся в JSON |
| `-effort` | Да для одиночного CLI-запроса без `-config` | `none`, `minimal`, `low`, `medium`, `high`, `xhigh` (для Codex также `max`, `ultra`); при `-config` задаётся в JSON |
| `-context` | Да для всех CLI-запросов, включая `-config` | Текст для анализа; `-` читает stdin. Для запуска UI не нужен |
| `-question` | Нет | Вопрос или критерий оценки |
| `-choices` | Да для одиночного запроса `choice` | Категории через запятую; при `-config` используется массив `choices` в JSON |
| `-levels` | Да для одиночного запроса `score` | Описания уровней через `\|`; при `-config` используется массив `levels` в JSON |
| `-concurrency` | Нет | Максимум параллельных запросов, положительное целое число; по умолчанию 5 |
| `-repeats` | Нет | Число оценок от 1 до 100; по умолчанию 1 |


Без конфига одна команда оценивает один вопрос. Для списка проверок используй `-config`.

## Конфигурации

Формат, команды и готовые файлы: [примеры конфигураций](docs/configurations.md).

Значение -config, начинающееся после пробелов с `{` или `[`, разбирается как JSON; остальные значения — пути к файлу. Конфиг должен быть объектом с checks. Путь с таким началом можно записать через `./`. Контекст внутрь конфига не помещается и всегда задаётся отдельно через -context.

Все проверки получают одинаковый контекст. Флаг -config совместим с -api-key, -context и -concurrency; остальные настройки задаются внутри JSON.

- `checks`: 1–100 проверок с уникальными непустыми `id`. `category` — необязательная подпись; несколько проверок могут иметь одну категорию, отдельного балла категории нет.
- В каждой проверке можно задать собственный `concurrency` — положительное целое без фиксированного верхнего предела. Если он не задан, используется общий лимит. Оба ограничения действуют одновременно: например, общий 10 и локальный 3 дают этой проверке не более 3 запросов. Локальный 20 при общем 10 не увеличивает общий потолок. `effective_concurrency` в результате показывает предел с учётом локального, общего лимитов и repeats. Поле `concurrency` внутри результата проверки показывает заданный или унаследованный лимит.
- `provider`, `model`, `effort`, `repeats` наследуются из `defaults`; поля проверки переопределяют их. Провайдер по умолчанию — `openrouter`; смешанный конфиг требует ключ для проверок OpenRouter. Если repeats нигде не задан — 1. `type` по умолчанию choice.
- `choices` и `levels` — массивы строк. Внутри элементов разрешены запятые и `|`.
- `question` — текстовый критерий для модели. CLI возвращает оценки без применения порогов или правил приёмки. Интерпретируй их за пределами конфигурации.
- `concurrency`: общий максимум одновременных запросов OpenRouter и процессов Codex всех проверок, включая повторы; любое положительное целое число, по умолчанию 5. Отдельного ограничения в пять оценок на проверку нет.
- `__external__` — необязательные данные для внешних инструментов: любое JSON-значение (объект, массив, строка, число, boolean или null). CLI не интерпретирует содержимое, не передаёт его модели и не использует при оценке, но возвращает его в `checks[].__external__`, в том числе при ошибке проверки. Если поле отсутствует в конфиге, оно отсутствует и в результате. Вложенные ключи произвольны; остальные поля конфига по-прежнему проверяются строго.
- Неизвестные поля, неверные настройки, повторяющиеся id отклоняются до первого API-запроса. Комментарии и несколько JSON-документов в файле не допускаются.

Результат содержит `checks` в порядке конфига, `check_count`, `completed_checks`, `attempt_count`, `usage` и `usage_complete`. У каждой проверки — прежние результаты и расход, id, категория, модель, effort и статус:

| Статус | Значение |
|---|---|
| `completed` | Получены все запрошенные оценки, независимо от их значений |
| `error` | Не удалось собрать все повторы |

`completed_checks` — число полностью выполненных проверок. Ошибка проверки не отменяет остальные. Код выхода 0 означает успешное выполнение, а не высокую оценку материала. Код 1 означает ошибку выполнения или входных данных; доступные результаты сохраняются в JSON. Верхний `usage` уже включает расход всех checks: повторно складывать их не нужно.

Поле `pass` больше не поддерживается. Удали его из старых конфигов: строгий парсер отклоняет неизвестные поля, чтобы прежние условия не игнорировались незаметно.

## Повторы и медиана

Параллелизм задаётся `-concurrency` (по умолчанию 5), без фиксированного верхнего предела. Например, `-repeats 100 -concurrency 100` запускает до 100 запросов одновременно. `-repeats 1` возвращает одиночный результат, без поля `aggregation`. При большем числе повторов `aggregation` равно `median`:

- `noul`: медиана значений `noul`.
- `score`: медиана итоговых баллов, а не балл от усреднённых распределений. Вероятности каждого вызова доступны в `samples`.
- `choice`: медиана вероятности каждой категории, затем выбор максимума. При равенстве побеждает первая категория из `-choices`. Медианы возвращаются как `median_probabilities`; их сумма не обязана равняться 1. Это не голосование большинством.

Для чётного количества оценок медиана равна среднему двух центральных значений.

Неверный JSON, отсутствие ответа, незавершённая генерация, неверные поля, вероятности вне диапазона и неправильная сумма вызывают до **трёх дополнительных попыток** на оценку: максимум `4 × repeats` запросов. Для распределения допускается отклонение суммы от 1 не более 0.01; принятую сумму CLI нормализует. Повтор сохраняет задачу, контекст и настройки, но добавляет в системную инструкцию только тип последней ошибки валидатора, без фактических значений и просьбу исправить ответ. История ошибок отдельная у каждого независимого повтора. HTTP/API-ошибки и сетевые сбои автоматически не повторяются. Таймаут одного HTTP-запроса или запуска Codex — 180 секунд.

Codex используется как оценщик без инструментов и пользовательских скиллов: инструменты не передаются ни в `tools`, ни через `additional_tools`. Ретраями и параллелизмом управляет Merilo, как для OpenRouter. [Настройки, причины ограничений и проверка совместимости](docs/codex.md#codex-используется-как-оценщик-без-инструментов).

Для Codex денежная стоимость недоступна: `usage.cost` отсутствует, `usage_complete` равно `false`. В смешанном конфиге стоимость включает только известный расход OpenRouter. Результат каждой проверки содержит `provider`, `model`, `effort`; Codex также возвращает `billing: "chatgpt_subscription"`.

## JSON и ошибки

Общие поля:

| Поле | Содержание |
|---|---|
| `type` | Режим |
| `repeats`, `completed` | Запрошенное и полученное число оценок |
| `attempt_count` | Число всех попыток, включая неуспешные |
| `samples` | Оценки в порядке повторов; внутри `result` и список `attempts` с `usage` и возможной `error` |
| `usage` | Сумма доступных числовых счётчиков всех попыток, включая отклонённые ответы |
| `usage_complete` | Во всех ли попытках доступны стоимость и основные счётчики токенов |

`usage.cost` — стоимость в USD по OpenRouter. `prompt_tokens` — вход, `completion_tokens` — выход, `total_tokens` — всего. Детали reasoning и кэша суммируются, если их вернул API. Нечисловые поля usage не агрегируются; оригинальные значения доступны в попытках.

При `usage_complete: false` стоимость и токены могут быть частичными: неизвестный расход не считается нулевым. Даже `true` не означает полноту всех необязательных вложенных счётчиков.

Если хотя бы одна оценка не получена, CLI выводит JSON с `error`, накопленной статистикой и без итоговой медианы, затем завершает работу с кодом 1. Ошибки также идут в stderr. Ошибки параметров до начала запросов возвращают только stderr и код 1. Успешный запуск завершается с кодом 0.

## Как использовать оценки

Медиана снижает влияние отдельных крайних ответов. Для сравнения версий фиксируй модель, effort, вопрос, уровни и число повторов. Оценки не являются калиброванными вероятностями; автоматическая валидация проверяет формат и числовые ограничения, а не истинность суждения. Объяснения оценок CLI не возвращает.
